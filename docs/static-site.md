# Static Seismographic

The Streamlit app needs a Python server running whenever someone has a page open. On Vercel that burned through the
free CPU allowance. The static site does all the work ahead of time and in the visitor's browser, so the host only
serves files.

- **Ahead of time** (`python -m staticbuild`, run locally and by GitHub Actions): read `data/snapshot`, run the
  existing `prm` code (scoring, history, outlook, validation, hotspots, interpretation, assessments, PDFs, exports) and
  write JSON, CSV, XLSX and PDF files into `web/`. Python stays the single source of truth for the model; nothing in
  `prm` is rewritten for the build.
- **In the browser** (`web/`): plain HTML, CSS and native ES modules, with no bundler and no build step. Everything
  that depends on a visitor's choice (custom weights `?w=`, stress test, compare, explorer, filters, builder) is
  computed in JavaScript from the JSON.
- **Hosting**: Vercel project `seismographic` with root directory `web`, framework "Other", no build command, no
  functions. Rewrites in `web/vercel.json` are CDN rules and use no function CPU. See DEPLOY.md.
- **Streamlit** stays for local use (`streamlit run streamlit_app.py`). The root `vercel.json` that deployed it is
  gone.

## Layout

```
staticbuild/                 Python package, run with: .venv/Scripts/python.exe -m staticbuild [--only core,news,...]
  __main__.py                runs every exporter (or the ones named with --only), then writes web/data/manifest.json
  common.py                  load_core() once, write_json(path, obj) (compact, NaN -> null), paths
  core.py                    the shared data files below + the static API
  <group>.py                 one module per page group, owning that group's files under web/data/<group>/
web/
  index.html                 the only HTML page (the shell); every route is rewritten to it
  vercel.json                rewrites + headers
  css/app.css                theme, layout, components (tokens as --sg-* from config.INK)
  js/app.js                  boot: load core data, router, sidebar, dock + Find, weights panel, footer
  js/lib/*.js                shared modules (see below)
  js/pages/<route>.js        one module per page: export async function render(main, ctx)
  data/                      generated by staticbuild (committed; never hand-edited)
  api/v1/                    generated static API (same JSON shapes as prm/api.py)
  files/                     generated downloads (CSV/XLSX) and briefs (PDF)
  tests/*.test.mjs           node --test parity tests against fixtures written by staticbuild/fixtures.py
scripts/serve_web.py         local server: serves web/, applies the same rewrites as vercel.json, no caching
```

## Page module contract

```js
// js/pages/<route>.js
export const title = 'Country profile';          // also the document title: `${title} · Seismographic`
export async function render(main, ctx) { ... }   // fill `main`; may return a cleanup function
```

`ctx` (built once by app.js, see js/lib/ctx.js):
- `ctx.core`: the parsed core files (config, countries, values, scores, history, meta), loaded once at boot.
- `ctx.weights()`: current weights from `?w=` or defaults; `ctx.scores()` / `ctx.history()` / `ctx.table()`: the
  default precomputed data when the weights are the defaults, otherwise recomputed in JS (lib/scoring.js) and cached
  per weights key.
- `ctx.params` (URLSearchParams), `ctx.go(path, params)`, `ctx.setParam(name, value)` (replaceState, no reload).
- `ctx.fetchJSON(url)`: cached fetch of anything under /data.
A page re-renders when the route or its query changes; keep tabs lazy (render a tab's content when first opened).

## Shared JS modules (js/lib)

- `ctx.js` router helpers and the ctx object; `format.js` numbers, populations, dates, signed values (same rules as
  prm/interpret.py `signed` and ui.fmt_population); `dom.js` tiny `h()` element helper, escaping.
- `scoring.js` a line-by-line port of prm/scoring.py `normalise`, `normalise_against`, `compute_scores`, `tier_for`,
  composite recomputation for history and `flag_counts`; must match Python to 1e-9 on the fixtures.
- `interpret.js` port of prm/interpret.py (readings, trend labels, signed numbers).
- `table.js` port of ui.master_table plus a sortable, accessible country table component (sticky header, tier
  cells, keyboard sortable, row link to `/country?country=ISO3`).
- `charts.js` port of prm/charts.py: functions with the same names returning Plotly figure objects
  `{data, layout}`, plus `plot(el, fig)` which lazy-loads Plotly (plotly.js 4.1.1, the version Python plotly 7.1.0
  embeds) and renders with the same config. The Python figure JSON for the default weights is written as fixtures and
  the tests compare traces and key layout fields.
- `globe.js` port of prm/globe.py (`risk_globe`): the same globe.gl code, data shape and behaviour, mounted as a
  normal element instead of a Streamlit component.
- `ui.js` ports of the presentational helpers in prm/ui.py: hero, tier badge and legend, pillar chip, flag image,
  country header, cite/source links, tabs bound to `?tab=`, segmented views bound to `?view=`, news list, video
  gallery, footer, data status, follow strip (localStorage, prm/follow.py).

## Look

Identical to the Streamlit app: black background (#000), JetBrains Mono everywhere (self-hosted: four woff2 files in
`web/vendor/fonts/`, declared in app.css; no request goes to Google Fonts), colours only
from config.INK / pillar colours / tiers / COUNTRY_COLORS (exported in config.json, emitted as `--sg-*` CSS variables),
safer = #74b1fe, riskier = #fd8078. h1 from hero, sections are h2. No kickers, gradients, glows or emoji other than the
existing severity/pillar markers. The app never links to the GitHub code. Plotly charts use the same template and
config as the Python figures (paper/plot background, font, colours, `displayModeBar` etc.).
Accessibility as in the Streamlit app: skip link, landmarks, visible focus, Find on `/` and Ctrl/Cmd+K, 44px targets
on touch, tables as the fallback for every chart, reduced motion respected.

## Core data files (staticbuild/core.py)

All JSON is compact. Country tables are column-oriented to stay small: `{"columns": [...], "rows": [[...], ...]}`
with `null` for missing values.

- `data/meta.json`: build time (UTC ISO), snapshot meta (from data/snapshot/meta.json), analysis year, version.
- `data/config.json`: APP_TITLE, APP_TAGLINE, pillars (key, label, short, default_weight, color, description),
  indicators (every field of config.Indicator that the pages use), tiers (label, lower, color), INK, COUNTRY_COLORS,
  chart colours (WORSE, BETTER, …), LOG_CAP_QUANTILE, PILLAR_MIN_SHARE, COMPOSITE_MIN_PILLARS, regions, source
  definitions used by cite/source_link.
- `data/countries.json`: the countries table (iso3, iso2, name, region, sub-region, income group, …).
- `data/values.json`: scoring.build_values for the analysis year (every column, incl. `__year` and context).
- `data/scores.json`: compute_scores with default weights (all columns incl. n_* indicator scores).
- `data/history.json`: full history (country-year rows with pillars, composite, tier, rank) since 2015.
- `api/v1/index.json`, `api/v1/countries.json`, `api/v1/countries/<ISO3>.json`, `api/v1/dictionary.json`: the same
  payloads prm/api.py returns.

### API filters

`/api/v1/countries` takes `?region=`, `?income=` and `?tier=`, as in prm/api.py: all given filters must match, the
match ignores case, and an unknown value gives an empty list. Unlike prm/api.py, values must be exact: a blank or padded value (`?tier=` or `?tier=%20High`)
also gives an empty list. Country codes in `/api/v1/countries/<ISO3>` must be upper-case (`/api/v1/countries/KEN`). A static host cannot filter, so the build writes one
file per combination that has results (`countries.region-<slug>.income-<slug>.tier-<slug>.json`) and
`countries.empty.json` for the rest. It then writes `has`/`missing` rewrite rules for them into `web/vercel.json`,
most specific first, ahead of the plain `/api/v1/countries` rule, which serves only requests with none of the three
keys. Do not edit these rules by hand: the next build regenerates them. `scripts/serve_web.py` applies the same rules
locally.

### Fragile States Index (FSI)

The FSI reuse terms are unconfirmed, so the site never stores or serves the FSI data. The build downloads it,
computes the benchmark with the default weights (compared countries, Spearman correlation, top-20 overlap) and writes
only those aggregates to `data/reference/fsi.json`. If the download fails, the last good file stays. The Methodology
page reads that file.
Page groups add their own files under `data/<group>/` (news, hotspots, cases, assessments, outlook, validation,
flows, events, videos, glossary, sources, …) from their own `staticbuild/<group>.py`.

## Things that were live and now refresh on a schedule

- News headlines (Bing/Google RSS, GDELT fallback): fetched by the build for the global feed and every country, kept
  as `data/news/<ISO3>.json` + `data/news/global.json`; refreshed by a daily workflow.
- Live data download: the weekly refresh-data workflow already refreshes the snapshot; it now also runs
  `python -m staticbuild` and commits `web/`.
- Hotspots: the daily refresh-hotspots workflow also rebuilds `data/hotspots/`.
- Fragile States Index: its reuse terms are unconfirmed, so the build stores only the derived benchmark statistics,
  never the FSI data itself.
- PDF briefs: built for every country with default weights (`files/briefs/<ISO3>.pdf`).
- Live video: YouTube embeds work unchanged.
